ИИ-ассистент для генерации тестовых материалов по документации ПТЭ (Правила технической эксплуатации) и другой нормативной документации ОАО «РЖД».

Проект помогает создавать тесты и пояснения на основе загруженных документов. Ориентирован на подготовку и проверку знаний сотрудников(Дежурных по станции) отдела ГВЦ.

## Основные возможности

- Загрузка документов (ПТЭ и другая документация)
- Построение RAG-системы по загруженным материалам
- Генерация тестовых вопросов и вариантов ответов
- Работа с контекстом и историей
- Поддержка голосового ввода/вывода
- Возможность обучения и использования собственной ML-модели

## Архитектура и структура

Проект написан на Python и развёртывается через Docker. Основные компоненты:

- `app.py` - точка входа и веб-интерфейс
- `rag_pipeline.py` - логика RAG
- `llm_provider.py` - работа с языковыми моделями
- `train_ml_model.py` + `model.pt` - обучение и использование собственной модели
- `chroma_db/` - векторное хранилище
- `agents/`, `services/` - агенты и сервисы
- `docker-compose.yml` + `Dockerfile` - контейнеризация

## Технологический стек

### Ядро системы
- **Python** - основной язык разработки. Удобен для работы с данными, моделями и быстрого прототипирования.
- **LangChain** - используется для построения цепочек генерации вопросов, управления промптами и интеграции RAG.
- **RAG (Retrieval-Augmented Generation)** -  Документы разбиваются на фрагменты, превращаются в эмбеддинги и сохраняются в векторной базе. При генерации вопроса система сначала находит релевантные куски документации, а уже потом просит модель сформулировать вопрос и ответы на их основе. Это снижает риск «галлюцинаций».

### Векторный поиск и эмбеддинги
- **ChromaDB** - лёгкая векторная база данных. Хранит эмбеддинги фрагментов ПТЭ и другой документации. Позволяет быстро находить семантически близкие куски текста по запросу.
- **Эмбеддинги (Hugging Face / Ollama)** - превращают текст в числовые векторы, чтобы можно было искать по смыслу, а не по точному совпадению слов.

### Языковые модели
- **LLM (локальные через Ollama или облачные)** - используются для генерации вопросов, вариантов ответов и пояснений. Локальные модели позволяют работать без отправки данных наружу (важно для внутренней документации).

### Интерфейс и дополнительные возможности
- **Веб-интерфейс** - позволяет загружать документы и получать сгенерированные тесты.
- **Речевые технологии** (`speech_utils.py`) - поддержка голосового ввода и вывода (распознавание и синтез речи).
- **Docker + Docker Compose** - упаковывает всё приложение в контейнеры. Упрощает запуск и развёртывание.

### Данные и хранение
- **Загружаемые документы** (`uploaded_docs/`, `data/`) - исходные материалы ПТЭ и другой документации, на которых строится генерация.
- **База данных** - для хранения сессий, истории или результатов генерации.

## Как это работает (упрощённо)

1. Пользователь загружает документы (ПТЭ и т.д.).
2. Документы разбиваются на фрагменты и индексируются в ChromaDB.
3. При запросе на генерацию теста система находит релевантные фрагменты через RAG.
4. LLM (или собственная модель) на основе найденного контекста генерирует вопросы, варианты ответов и пояснения.
5. Результат возвращается пользователю (текстом или голосом).

## Какие требования

- Автоматизация создания тестовых материалов по сложной нормативной документации
- Снижение времени на подготовку вопросов для обучения и аттестации
- Демонстрация практического применения RAG и LLM в железнодорожной тематике
- Возможность работы с внутренней документацией без отправки данных в облако (при использовании локальных моделей)
